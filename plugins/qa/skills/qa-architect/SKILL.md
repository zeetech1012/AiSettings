# SKILL: QA_ARCHITECT (Анализ покрытия)

## Цель
Инвентаризация тестового покрытия проекта (Kotlin/KMP + Go) и формирование рекомендаций по покрытию.

## Алгоритм действий

1. **Сканирование кода**:
   - Найдите все Kotlin тесты в каталогах `src/androidTest/` и `src/test/`.
   - Найдите все Go тесты с суффиксом `*_test.go`.
   - Используйте команды `find`, `grep` и `tree` (через инструмент `Bash`) для сбора структуры директорий и списка файлов.

2. **Сравнение с модулями проекта**:
   - Сопоставьте файлы тестов с модулями бизнес-логики (например, `httpHandler/`, `dbHelper/`, `tokens/` в Go или соответствующими пакетами в Kotlin).
   - Выявите модули, которые не имеют сопоставленных тестов.

3. **Составление Markdown-отчета**:
   - Сформируйте Markdown-таблицу со следующей структурой:
     ```markdown
     | Модуль | Статус покрытия | Заметки |
     |---|---|---|
     | `httpHandler` | Покрыт | Юнит-тесты покрывают `/auth` endpoint |
     | `dbHelper` | Не покрыт | Требуются интеграционные тесты с SQLite/MySQL |
     ```

4. **Формирование плана покрытия (вывод — только в Obsidian-vault)**:
   - **СТРОГО:** не создавать `.md` в рабочем каталоге проекта (правило `~/.claude/CLAUDE.md`).
     План покрытия пишется/дополняется **только** через MCP-сервер `obsidian`
     (`vault_write` — создать/перезаписать, `vault_append` — дописать) по пути
     `Company/Projects/<название_проекта>/QA/coverage_plan.md`. Если папка/проект не очевидны —
     уточните у пользователя, не угадывайте.
   - Рекомендации должны содержать: имя модуля, приоритет покрытия, рекомендуемые типы тестов (unit, integration, UI).

## Пример вызова
```bash
# Поиск всех файлов тестов Go
find . -name "*_test.go" -type f

# Поиск всех Kotlin-тестов
find . -path "*/src/*test*/*.kt" -type f
```
