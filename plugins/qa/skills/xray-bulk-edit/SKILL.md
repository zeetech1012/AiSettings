# SKILL: XRAY_BULK_EDIT

Паттерн выведен из трёх применений 2026-09-15/16: 96 `Generic Test Definition` на Kotlin-имена,
16 заголовков Python-эпохи, 124 шага для 29 ручных проверок. Каждый раз одна и та же дисциплина,
поэтому она вынесена сюда. Общие правила Xray — в глобальном `CLAUDE.md`, раздел
«Xray в Jira DC» и подраздел «Массовая правка в Jira и Xray — скриптом для владельца».

## Когда применять

Правка, затрагивающая больше нескольких задач: определения Generic Test, заголовки, метки,
компоненты, привязка к Test Set и Test Plan, шаги Manual Test. Для одиночной правки скилл не нужен.

## Железное ограничение

Запись в Jira из сессии агента чаще всего отклоняет классификатор харнесса — и через `curl`, и через MCP.
Общего одобрения в чате недостаточно; проходит запись по прямой просьбе владельца о конкретном действии
в текущем сообщении. Обходить запрет нельзя, поэтому порядок неизменный: агент

1. готовит данные правки и скрипт,
2. прогоняет **сухой** режим (только чтение),
3. отдаёт владельцу одну команду для запуска через `!` — либо выполняет запись сам, если владелец прямо об этом попросил,
4. после запуска фиксирует результат в vault, журнале и памяти.

## Процедура

1. **Источник истины — не догадка.** Тексты и значения выводятся из кода (`@TmsLink` → `fullName`,
   `@DisplayName`), из кода сервиса или из тест-плана. Ключи задач не выдумывать: сверить запросом.
2. **Снять текущее состояние** (`GET`) и посчитать дельту: что уже правильно, что меняется, что
   отсутствует. Оракул полезен: если часть объектов уже приведена к целевому виду, сравнение с ними
   проверяет саму формулу правки. Так проверялись 47 из 143 определений — расхождений не было.
3. **Проверить метод** для нового вида правки: `OPTIONS <endpoint>` печатает `Allow`. Шаги Manual
   принимают только `PUT`; поля задачи — `PUT /rest/api/2/issue/<key>`.
4. **Сложить правку в файл данных** (TSV: ключ, затем JSON тела), а не внутрь скрипта. Источник
   текстов дополнительно сохранить заметкой в vault: сессионный каталог недолговечен, заметка нет.
5. **Сухой прогон** — печатает по строке на объект и ничего не отправляет. Глазами сверить выборочно.
6. **Передать владельцу** обе команды: сухую и рабочую. Не описывать словами, а дать готовую строку.
7. **Зафиксировать итог**: отчёт скрипта, число изменённых объектов, что осталось открытым.

## Три обязательных свойства скрипта

| Свойство | Зачем |
|---|---|
| сухой прогон `--dry` | правка проверяется до записи, вывод читаем человеком |
| защита от повторного применения | записи Xray **складываются**: второй запуск шагов даёт дубли, а уборки осиротевших объектов в Jira DC нет |
| проверка результата чтением | успешный код ответа не означает применённую правку; сверяется фактическое значение и печатается `ok=N fail=0` |

Готовый скрипт: `scripts/xray_bulk_edit.py` (только stdlib). Режимы:

```
python3 xray_bulk_edit.py fields data.tsv --dry      # поля задач: PUT /rest/api/2/issue/<key>
python3 xray_bulk_edit.py fields data.tsv            # запись + проверка чтением
python3 xray_bulk_edit.py add labels.tsv --dry       # дописать в поле-список, не стирая имеющееся
python3 xray_bulk_edit.py add labels.tsv             # PUT {"update": {"labels": [{"add": …}]}}
python3 xray_bulk_edit.py steps steps.tsv --dry      # шаги Manual: PUT /rest/raven/1.0/api/test/<key>/step
python3 xray_bulk_edit.py steps steps.tsv            # отказывается работать, если шаги уже есть
python3 xray_bulk_edit.py folders folders.tsv --dry  # раскладка по папкам Test Repository
python3 xray_bulk_edit.py folders folders.tsv        # создаёт недостающие папки, переносит тесты
```

**Режим `folders` — раскладка Test Repository.** Тело строки — `{"folder": "/Корень/Подпапка"}`. Текущее место
читается из поля `Test Repository Path` (`customfield_10309`), в дельту попадают только тесты не на месте. Весь файл
проверяется до первой записи: путь начинается с `/`, без пустых сегментов, у ключа одна папка. Папки создаются
по сегментам от корня. Проверка чтением сверяет путь каждого теста и печатает `ok=N fail=M`. Применено 23.09.2026
к IOT: 162 теста, 44 папки. 🟡 Перенос теста, который уже лежит в другой папке, через `add` не проверялся:
23.09 переносились только тесты вне папок.

**Режим `add` — для полей-списков** (метки, компоненты). `fields` заменяет значение целиком и стёр бы
разметку витрины покрытия (`level-*`, `type-*`, epic, feature), поэтому дописывание идёт глаголом
`update`. Идемпотентность здесь встроенная: уже присутствующее значение в дельту не попадает.
Тело строки — `{"<поле>": [значения]}`, смысл «обеспечить наличие».

Формат TSV — ключ, табуляция, JSON тела. Для `fields` тело это содержимое `fields`:

```
DEMO-60	{"customfield_10302": "ru.company.qa.authhttp.entities.BatchesTests.batchesAnonDenied"}
DEMO-61	{"summary": "Анонимный запрос к binding-эндпоинту отклонён → 4xx"}
DEMO-62	{"step": "Given: инстанс отвечает", "data": "адрес инстанса", "result": "200 на /api/stats"}
DEMO-63	{"labels": ["ru.company.qa.authhttp.recovery.RecoveryEdgeCasesTests.recoveryMalformedLogin"]}
DEMO-64	{"folder": "/Auth HTTP/Login"}
```

Порядок строк для шагов = порядок шагов в задаче.

## Поля Xray в Jira DC

| Поле | Идентификатор |
|---|---|
| Test Type | `customfield_10300` |
| Generic Test Definition | `customfield_10302` |
| Test Sets association | `customfield_10305` |
| Test Plans association | `customfield_10307` |
| Tests association with Execution | `customfield_10313` |

Шаги: `/rest/raven/1.0/api/test/<key>/step`. Состав прогона: `/rest/raven/1.0/api/testexec/<key>/test?page=1&limit=200`.

Идентификаторы типов задач Xray (проверено 23.09.2026 на HW): `10200` Test · `10201` Test Set · `10202` Test Execution ·
`10203` Pre-Condition · `10204` Test Plan · `10205` Sub Test Execution. 23.09 перепутанные `10201` и `10203` создали
лишний Pre-Condition вместо набора.

Прочие проверенные вызовы (23.09.2026):

| Действие | Вызов |
|---|---|
| дерево репозитория | `GET /rest/raven/1.0/api/testrepository/<P>/folders` → `{allTestsCount, allOrphanTestsCount, folders}` |
| создать папку | `POST …/testrepository/<P>/folders/<parentId>` `{"name": …}`, корень — `parentId = -1` |
| переименовать папку | `PUT …/testrepository/<P>/folders/<id>` `{"name": …}`; путь у тестов обновляется сам |
| удалить папку | `DELETE …/testrepository/<P>/folders/<id>` |
| тесты папки / перенести | `GET …/folders/<id>/tests?allDescendants=false&page=1&limit=500` / `PUT …/folders/<id>/tests` `{"add": [ключи]}` |
| исполнитель Test Run | `PUT /rest/raven/1.0/api/testrun/<id>/assignee?user=<username>` |
| связь «тест проверяет задачу» | `POST /rest/api/2/issueLink` с типом Tests, `inwardIssue` = тест, `outwardIssue` = задача |

## Ловушки, проверенные на инстансе

- **`POST` для шагов не разрешён**, только `PUT`, по одному телу на шаг.
- **`testInfo` рядом с `testKey` рушит импорт целиком** (проверено 2026-09-17; прежняя запись
  «импорт игнорирует testInfo» неверна): Xray DC отвечает `HTTP 200`, создаёт Test Execution и
  отвергает весь список тестов — `{"error":[{"messages":["Invalid Test Type: Generic."]}]}`.
  Определения существующих задач выравнивает отдельная правка или задача `xrayStructure`.
- **Успех импорта считается по `testIssues.success`**, а не по коду ответа: два прогона 2026-08
  прошли «успешно» и не доставили ни одного результата.
- **Успех импорта не равен доставке результатов**: проверять число прогонов внутри Test Execution.
- **Test Repository Path (`customfield_10309`) полем задачи не задать** — инстанс отвечает
  `Invalid Test Repository Path` на несуществующую папку. Папки создаются и заполняются API репозитория
  (таблица выше, режим `folders`), поле потом Xray заполняет сам.
- **Перенести папку целиком нельзя**: у `PUT` на папку нет поля родителя (`parentId` → 400 Unrecognized field,
  `parent` числом → 400, объектом или `testRepositoryPath` → 500). Переносятся тесты, пустая папка удаляется.
- **`/` в имени папки недопустим** — это разделитель пути репозитория; `Формирование белых списков (/sessions/api)`
  пришлось сократить.
- **Файл данных проверять целиком до первой записи.** 23.09 проверка длины сработала посреди записи TSV, и три строки
  ушли в Jira раньше остальных. Режим `folders` валидирует весь файл заранее; для других видов правки — так же.
- **Конвертер Markdown в разметку Jira ломает `_`, `*` и `{}`** внутри обратных кавычек: после
  записи комментария сверять сохранённый текст.
- **Сетевой сбой на середине прохода — норма, а не исключение** (2026-09-17/18): инстанс временами
  отвечает по 20 секунд и рвёт соединение по таймауту, а две копии скрипта разом исчерпывают
  локальные порты (`OSError: [Errno 49] Can't assign requested address`). Поэтому `call()` повторяет
  запрос с нарастающей паузой, а **две копии одновременно не запускать**: они не ускоряют проход,
  но гарантированно валят обе. Прерванный прогон повторяется без последствий — дельта считается заново.

## Границы

- **Test-задачи руками не создавать** — канон: Generic Test появляется импортом прогона.
  Скилл правит существующие объекты, а не заводит новые.
- **Ничего не удалять** без явного решения владельца по конкретному объекту: удаление Test Execution
  необратимо и уносит историю прогонов.
- **Секреты из кода и сценариев установки** в тела правок и шаги не копировать.
- Если правка меняет смысл покрытия (перенос задач между планами, смена типа теста), сначала вопрос
  владельцу, потом скрипт.
