# SKILL: KMP_UNIT_COVERAGE

Процедура доведения покрытия KMP-приложения до целевого процента. Проверена на `energy-app-native`:
контур **22,6 % → 46,4 %**, 322 → 647 `@Test` за две сессии, семь найденных дефектов.

**Не применять** для instrumented/UI-тестов на устройстве (там правила гайдлайна мобилки) и для
backend-наборов над HTTP (там `qa-monorepo`).

---

## Шаг 1. Метрика прежде тестов

Пока не назван знаменатель, процент бессмысленен. **Считать по «логическому контуру»**, исключив из
знаменателя код, который выбранный уровень тестов не исполняет в принципе.

```kotlin
// build.gradle.kts модуля
kover {
    reports {
        filters {
            excludes {
                annotatedBy("androidx.compose.runtime.Composable")
                classes("*ComposableSingletons*", "<generated-resources>.*", "<ui-libs>.*")
                packages("theme", "koin")   // тема и граф DI
            }
        }
    }
}
```

```bash
./gradlew :<module>:testDebugUnitTest --continue
./gradlew :<module>:koverXmlReport -x :<module>:testDebugUnitTest   # → build/reports/kover/report.xml
```

Разница не косметическая: на `energy-app-native` один и тот же код даёт **11,7 %** по модулю целиком и
**46,4 %** по контуру — 60 % знаменателя составлял Compose-UI, не исполняемый на JVM-хосте.

**Правило называния цифры:** процент всегда вместе с контуром, датой и командой пересборки. При смене
фильтров пересчитать все прежние срезы, иначе история врёт молча.

## Шаг 2. Приоритет по стоимости строки

Цели берутся не «по интуиции», а из отчёта: топ классов по непокрытым строкам.

```python
import xml.etree.ElementTree as ET
r = ET.parse("build/reports/kover/report.xml").getroot()
def line(el):
    c = next((x for x in el.findall("counter") if x.get("type") == "LINE"), None)
    return (int(c.get("missed")), int(c.get("covered"))) if c is not None else (0, 0)
outer = {}
for p in r.findall("package"):
    for cl in p.findall("class"):
        m, c = line(cl)
        o = cl.get("name").split("$")[0]          # внутренние классы и лямбды — к внешнему
        b = outer.setdefault(o, [0, 0]); b[0] += m; b[1] += c
for o, (m, c) in sorted(outer.items(), key=lambda x: -x[1][0])[:20]:
    print(f"{m:5d} непокрыто  {100*c/(m+c):5.1f}%  {o}")
```

**Порядок волн** (дешевле → дороже за строку):

| Волна | Область | Чем берётся |
|---|---|---|
| 1 | data: repository, api, dto, mappers | MockEngine + in-memory дубли хранилищ |
| 2 | ViewModel | дубли уровня репозитория + `StandardTestDispatcher` |
| 3 | domain: usecase, util, manager, states | чистые component-тесты, часто закрываются попутно волнами 1–2 |
| 4 | инфраструктура: конфиг клиента, метаданные, роуты | конфиг-смоук и проверки целостности справочников |

Перед каждой волной — замер; после — новый срез в карту эффорта.

## Шаг 3. Два уровня фикстур, и путать их нельзя

### Репозитории — интеграционно поверх `MockEngine`

Настоящие `Api` + `RepositoryImpl` + DTO + mapper, подменён **только транспорт**. Один тест закрывает
четыре слоя и держит фактический контракт бэкенда: путь, метод, query, тело, коды ответа.

```kotlin
class MockHttp(handler: suspend MockRequestHandleScope.(HttpRequestData) -> HttpResponseData) {
    val requests = mutableListOf<HttpRequestData>()
    val client = HttpClient(MockEngine { req -> requests += req; handler(req) }) {
        expectSuccess = true                     // зеркалит прод-конфиг клиента
        install(ContentNegotiation) { json(Json { ignoreUnknownKeys = true; isLenient = true }) }
        defaultRequest { host = BuildKonfig.BASE_URL; url { protocol = URLProtocol.HTTPS } }
    }
    val lastRequest get() = requests.last()
}
```

Клиент обязан зеркалить продовый: иначе тест проверяет конфигурацию, которой в проде нет.

### Экраны — поверх дублей уровня репозитория

`MockEngine` в тесте ViewModel **не работает**: экран стартует через `viewModelScope.launch`, движок
отвечает на своём диспетчере, `advanceUntilIdle()` до него не дотягивается — проверка идёт раньше ответа
(симптом: `null` вместо данных, `Idle` вместо `Error`, тест «падает без причины»).

```kotlin
@BeforeTest fun setUp() { Dispatchers.setMain(StandardTestDispatcher()) }
@AfterTest  fun tearDown() = Dispatchers.resetMain()

@Test fun `сценарий`() = runTest(dispatcher) {
    val vm = buildVm()          // настоящие use case поверх Fake*-репозиториев
    advanceUntilIdle()
    vm.onAction()
    advanceUntilIdle()
    assertEquals(expected, vm.uiState.value.field)
}
```

Задержки, которые экран держит намеренно (сообщение об успехе на 2 секунды), проверяются
`advanceTimeBy(1_000L)`: `advanceUntilIdle()` проглотит окно целиком.

### Сервис двоичного протокола — дубль отвечает внутри callback отправки

Сервис, который общается с устройством через колбэк отправки и поток входящих байт (шина, сокет,
BLE-характеристика), тестируется без движения виртуального времени: дубль перехватывает кадр в
`sendCallback`, разбирает его и кладёт ответ в поток **до того**, как сервис начнёт этот поток читать.

```kotlin
class FakeBus(service: SerialService) {
    val requests = mutableListOf<Request>()
    var reply: (Request) -> Reply? = { Reply() }
    init {
        service.sendCallback = { frame ->
            val request = decodeRequest(frame)   // разбор кадра, проверка CRC
            requests += request
            reply(request)?.let { service.appendData(encodeReply(it)) }
        }
    }
}
```

Почему это работает: сервис сначала зовёт колбэк, потом начинает разбор. К моменту разбора байты уже
в канале, `receive()` не приостанавливается, таймаут не наступает. Молчание прибора (`reply = { null }`)
упирается в таймаут по виртуальному времени и возвращает `null` мгновенно.

**Контрольную сумму в дубле считать независимой реализацией**, а не звать функцию проверяемого класса:
иначе ошибка в прод-алгоритме совпадёт с ошибкой в ожидании, и тест её не увидит. Если внешнего описания
протокола нет, полином эталоном не сверить — тогда золотые векторы помечаются 🟡 и подтверждаются первым
живым прогоном на приборе.

Приём окупается сразу на нескольких классах: кодек кадра, командный слой каждого прибора и репозитории,
которые этот сервис используют.

**Общую фикстуру** на группу экранов (менеджеры, которые тянут по пять use case) заводить один раз и
переиспользовать — она окупается со второго теста.

## Шаг 4. Дисциплина находок

- **Дефект, найденный тестом, остаётся красным repro** до фикса. Прод-код не правим, тикет заводит владелец.
  Красные считать отдельно от «сломанных»: в отчёте прогона у каждого красного есть номер дефекта.
- **Блокер тестируемости — тоже дефект**, и оформляется с указанием готового шва, если он есть в коде.
  Пример: экран дёргал push-SDK в `init`, хотя абстракция `PushNotificationsProvider` уже существовала
  и уже использовалась соседним use case — правка на одну строку, а без неё непокрываемы две трети экрана.
- **Поведение, которое похоже на дефект, но спорно** (команда уходит на прибор до проверки кэша),
  фиксируется **зелёным** тестом с пометкой «зафиксировано текущее поведение, кандидат в дефект» —
  и выносится владельцу вопросом, а не молчаливым красным.

## Шаг 5. Срезы и след в вики

После каждой волны: срез в карту эффорта (`wayfinder/<effort>/map.md`, таблица «Метрика» с датой),

## Ловушки, стоившие времени

| Симптом | Причина | Лечение |
|---|---|---|
| `None of the following candidates is applicable` на `assertContains` | третий позиционный параметр — `ignoreCase`, не message | `message = "…"` именованным или в комментарий |
| `Syntax error: Unclosed comment` с указанием на последнюю строку файла | `/*` внутри KDoc: строка вида `` `api/*` `` открывает вложенный комментарий | писать `api/…` |
| Тест ViewModel видит пустое состояние | HTTP-мок отвечает на чужом диспетчере | дубли уровня репозитория |
| Прогон падает исключением из `init` ViewModel | исключение из `viewModelScope.launch` валит тест, несмотря на `SupervisorJob` | синхронные тесты без `runTest`, либо фикс шва в прод-коде |
| Сломалась компиляция instrumented после правки unit-тестов | каталог дублей подключён к обоим сорсетам через `kotlin.srcDir` | файлы с «unit-only» зависимостями класть в отдельный пакет; гонять обе задачи |
| `Unresolved reference` в чужих тестах | перезаписан существующий `Fake*` | перед созданием дубля смотреть каталог; чужие править дополнением, восстановление — `git checkout --` |
| Ресурсы Compose недоступны из `commonTest` | `Res.string.*` не генерируется для этого сорсета | брать значение через прод-функцию, которая его возвращает |
| Тест на маппер «не сходится» по числу | маппер переводит единицы (кВт → Вт) | сверять с кодом маппера, а не с ожиданием «по смыслу» |
| Ветка кода недостижима, хотя метод публичный | значение, от которого она зависит, задаётся только внутри корутины на зашитом `Dispatchers.IO` | покрывать нечего до инжектируемого диспетчера; фиксировать наблюдаемое и оформлять блокер дефектом |
| Тест даты падает на смещении в несколько часов | прод-код нормализует дату в локальной зоне, а в тесте захардкожена полночь UTC | считать границы суток через `kotlinx-datetime` в зоне машины, не константой |
| Промежуточный флаг загрузки не ловится между `runCurrent()` | дубли не приостанавливаются, весь `viewModelScope.launch` проходит за один проход планировщика | проверять наблюдаемый итог, а не транзитное состояние |
| Новое значение перечисления молча выпадает из разбора | таблица соответствия написана списком и не сверяется с самим перечислением | сверять ключи таблицы с `Enum.entries` — сторож ловит добавление значения без разбора |
| Тест ViewModel не завершается, хотя все ассерты прошли | экран держит бесконечный тикер (`while (isActive) { emit; delay }`) в `viewModelScope`, а `runTest` в `finally` дренирует планировщик до пустоты (`advanceUntilIdleOr { false }`) | отменять `vm.viewModelScope.cancel()` в `finally` каждого теста; время двигать только `runCurrent()` и `advanceTimeBy()`, `advanceUntilIdle()` не вызывать |
| Состояние экрана «мигает» или ассерт срабатывает раньше загрузки графика | ViewModel запускает работу на зашитом `Dispatchers.IO` (`viewModelScope.launch(Dispatchers.IO)`), тестовый диспетчер её не видит | такие ветки не покрывать и не двигать виртуальное время до их запуска; блокер тестируемости оформлять дефектом с указанием шва — инжектируемый диспетчер |
| Ассерт «побочный эффект после сохранения» красный, хотя действие выполнено | побочный эффект (перезапись кэша) стоит в коде ПОСЛЕ `delay` окна статуса внутри `onSuccess` | читать порядок операций в исходнике до написания ожидания; проверять в две фазы: `runCurrent()` → после `advanceTimeBy(окно)` |

**Обязательная валидация после любой правки в `commonTest`:**

```bash
./gradlew :<module>:compileDebugAndroidTestKotlin :<module>:testDebugUnitTest --continue
```

## Чек-лист волны

1. Замер сделан, знаменатель назван, топ непокрытых классов выписан.
2. Уровень фикстуры выбран правильно (репозиторий → MockEngine, экран → дубли).
3. В KDoc класса названы техника тест-дизайна и границы: что покрыто и что осознанно нет.
4. Негативы есть: отказ сервера, не-JSON тело, пустой ответ, отсутствие обязательных данных.
5. Обе validation-задачи зелёные, красные — только зарегистрированные repro.
6. Срез записан в карту и `log.md`, handoff обновлён.
