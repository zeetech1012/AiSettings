Выбор слоя — 3 вопроса

  • Чистая логика, без платформенных API? → commonTest (только multiplatform-либы).
  • Нужен платформенный рантайм/поведение? → платформенный unit set (androidUnitTest/iosTest).
  • UI? shared Compose без backend → runComposeUiTest; Android-девайс → Kaspresso; iOS-специфика → XCUITest.

Железные правила

В commonTest — только мультиплатформенные библиотеки. JVM-only (MockK/Robolectric/java.*) ломает Native-таргет.
runComposeUiTest — не JUnit TestRule; вызов функции + ComposeUiTest receiver; finders/matchers как в Jetpack Compose.
compose.uiTest держать в iosTest/платформенном set'е, не в commonTest — иначе Compose-runtime утечёт в JVM-host unit.
Compose MP 1.11: v2 ComposeUiTest + StandardTestDispatcher по умолчанию; runComposeUiTest/runSkikoComposeUiTest deprecated. С 1.9 — suspend-лямбда + awaitIdle().

Локатор-контракт (для UI-слоёв)

  • Modifier.testTag("…") в Compose → на Android = semantics, на iOS = accessibilityIdentifier → один словарь локаторов для Compose-test и XCUITest.
  • Приоритет: testTag > contentDescription > видимый текст.
