# SKILL: DOC_SYNC

Один скилл на три адресата. Общая часть — здесь; всё, что зависит от системы (транспорт, разметка,
ловушки, скрипты), лежит в подкаталоге адресата.

| Адресат | Куда смотреть | Транспорт |
|---|---|---|
| **Huly** (`tracker.example.com`) | `huly/notes.md`, реестр `huly/registry.json` | MCP `huly` (`create_document` / `edit_document`) |
| **Docmost** (`docmost.example.com`) | `docmost/notes.md`, реестр `docmost/registry.json`, `docmost/scripts/docmost_api.py` | внутренний REST (официальный MCP закрыт EE-лицензией) |
| **Confluence DC** (`confluence.example.com`) | `confluence/notes.md`, реестр `confluence/registry.json`, `confluence/upload.py`, `confluence/md2wiki.py` | REST по PAT, markdown → wiki-разметка |

## Цель и инварианты — одинаковы для всех трёх

**Источник истины — Obsidian-vault.** Адресат — выгрузка для команды, а не место правки: страница,
исправленная руками в интерфейсе, будет затёрта следующей выгрузкой.

1. **Один файл vault = один документ у адресата.** Повторный запуск **обновляет** существующий
   документ по идентификатору из реестра, а не создаёт новый.
2. **Никогда не создавать документ для файла, у которого есть запись в реестре.** Создание допустимо
   только для файла без записи — и сразу после него запись добавляется в реестр.
3. **Перед любой записью свериться с реестром.** Реестр лежит в подкаталоге адресата и правится либо
   скриптом этого адресата, либо самим скиллом — но не «на глаз» руками.
4. **Переименование — это правка заголовка**, а не пересоздание документа.
5. **`.md` создаются и правятся только в Obsidian** (правило vault'а); адресат правится через свой
   транспорт. Реестр — служебный JSON скилла, не документация.

Реестры **раздельные и не сливаются**: в них идентификаторы разных систем (`docId` у Huly, `pageId`
у Docmost и Confluence), общего пространства имён нет.

## Порядок работы

1. **Определить адресата и объём.** Пользователь назвал конкретные файлы — синхронизируем их;
   «обнови все доки» — идём по записям реестра нужного проекта.
2. **Прочитать реестр адресата**, найти записи для целевых файлов.
3. **Прочитать источник из vault** (`mcp__obsidian__vault_read` либо Obsidian CLI).
4. **Преобразовать содержимое под адресата** — правила в `<адресат>/notes.md`: у каждой системы своя
   беда с разметкой (лоссовая конвертация в wiki, нерендерящиеся callouts, mermaid вложением).
5. **Записать**: есть запись в реестре → обновление по идентификатору; нет → создание плюс новая
   запись в реестре.
6. **Отчёт**: что обновлено, что создано, что пропущено и почему.

**Сначала всегда сухой прогон**, если адресат его поддерживает (`--dry` у Confluence): выгрузка
трогает документы, которые читают коллеги.

## Общее для преобразования

- Frontmatter (`---…---`) — убрать.
- H1 статьи — убрать: у страницы адресата собственный заголовок, иначе он задвоится.
- Wikilinks `[[…]]` — заменить читаемым текстом либо ссылкой на страницу адресата, если цель уже в реестре.
- Экранирование `\|` в таблицах — снять, это специфика Obsidian.
- Эмбеды изображений на пути vault — убрать либо приложить вложением, если адресат это умеет.

## Wiki-дисциплина

Выгружается **export-слой** (`Company/Projects/…`). Рабочий слой (`Company/_wiki/…`) наружу не идёт:
там планы, аудиты, карты и заметки, адресованные агенту, а не коллегам. Ссылки между деревьями
внутри export-документов не ставим — они утекут вместе со статьёй.

## Анти-паттерны

- ❌ Создать документ, не проверив реестр → дубль статьи у адресата.
- ❌ Править реестр руками там, где его ведёт скрипт.
- ❌ Править страницу в интерфейсе адресата вместо источника в vault.
- ❌ Выгружать рабочий слой вики целиком «за компанию».
- ❌ Сливать реестры разных адресатов в один файл.
