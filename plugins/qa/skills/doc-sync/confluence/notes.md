# Doc-sync → Confluence DC

> Адресатная часть скилла. Общие правила — в `SKILL.md` уровнем выше.
> Реестр `registry.json`, скрипты `upload.py` и `md2wiki.py` — рядом с этим файлом.
> `upload.py` ищет реестр в своём каталоге, поэтому они лежат вместе.
> Запуск: `cd ~/.claude/skills/doc-sync/confluence && python3 upload.py <SPACE> <prefix> "<vault-path>" --dry`


> Запись идёт **напрямую в REST API** (`/rest/api/content`) скриптом `upload.py`, а не через
> MCP `mcp-atlassian` (`confluence_*`): его markdown-конвертация лоссовая (та же проблема, что
> в Jira — см. skill `jira-service-issue`), он не грузит дерево каталогов пакетно и не умеет
> mermaid → SVG-вложения. Читать/искать в сессии MCP-инструментами можно.

## Запуск

```bash
# сначала dry-run: печатает создать/обновить/переименовать без записи
python3 upload.py <SPACE> <проект-префикс> "Company/Projects/<проект>" --dry
# боевой прогон (родитель по умолчанию — homepage пространства)
python3 upload.py <SPACE> <проект-префикс> "Company/Projects/<проект>" [--parent <pageId>]
```

Зависимости: python3 (stdlib), `curl` (multipart-вложения), `npx` + Chromium
(`@mermaid-js/mermaid-cli` — рендер диаграмм; ставится сам при первом вызове).

**После переименований нужен второй прогон.** Карта ссылок (`LINKMAP`) читается из registry
при импорте модуля, а registry перезаписывается в конце прогона: на первом проходе ссылки
разрешаются в прежние заголовки.

## Как строится дерево

- Дерево vault → дерево страниц: подкаталог = страница-раздел, его файлы — дети.
- `README.md` каталога становится страницей-разделом этого уровня (корневой README —
  родителем всего дерева); каталог без README получает страницу-заглушку.
- **Заголовок страницы** = H1 файла с префиксом проекта: title в Confluence уникален
  в пределах ПРОСТРАНСТВА, а в vault имена типа `architecture_context.md` повторяются
  в каждом проекте. Коллизия внутри проекта → к заголовку добавляется имя файла.
- Внизу каждой страницы — `{info}`-футер «источник — такой-то путь в vault, правки в источник».
- Страница с шестью и более разделами второго уровня получает `{toc:maxLevel=2|minLevel=2}`
  перед первым разделом (`add_toc`). Макрос ставится при синхронизации, в исходнике vault
  оглавления нет: там его рисует сама Obsidian.
- Wikilinks разрешаются по registry в заголовки страниц (`resolve_links`), включая
  межпроектные; неизвестные цели остаются как есть.

## Ловушка — цепочка `ancestors` не пересчитывается у потомков

Страница переехала под нового родителя → у её **потомков** в REST-поле `ancestors` остаётся
прежний путь. Хлебные крошки в UI, дерево в боковой панели и запросы CQL `ancestor = <id>`
при этом верные (проверено на живом инстансе 2026-08-03) — расходится только это поле, то
есть страдают интеграции, которые его читают.

Лечится **реальной сменой родителя**: перенести страницу под другого родителя и вернуть
назад, PUT с телом из `body.storage`, чтобы содержимое осталось байт-в-байт. PUT с тем же
родителем поле не обновляет; endpoint `move` в Confluence DC 9.2.22 отсутствует (HTTP 404
на `/rest/api/content/{id}/move/{position}/{target}` и на `/rest/experimental/...`).

**Порядок — строго сверху вниз.** Цепочка вычисляется из цепочки родителя, поэтому лист,
починенный раньше своего родителя, скопирует битый путь. Чинить волнами: в каждой волне
только те страницы, чей родитель уже здоров.

Обычный прогон `upload.py` цепочки не портит и не лечит: он передаёт `ancestors` с прямым
родителем, а этого для пересчёта недостаточно.

## Mermaid

Confluence DC сам mermaid не рисует. `upload.py` рендерит блоки **поштучно** через `mmdc`
(одна битая диаграмма не валит остальные), кладёт `diagram-N.svg` вложениями страницы,
а `md2wiki.py` ставит в текст `!diagram-N.svg|width=900!` + исходник под `{expand}`.
Невалидные блоки перечисляются в конце прогона — чинить в источнике.

## md2wiki.py — правила, проверенные на живом инстансе

Конвертер собственный, порядок преобразований важен (код-блоки → блочные правила →
инлайн → экранирование). Ключевые ограничения Confluence wiki-разметки:

- `[текст]` — всегда ССЫЛКА, а не литерал → все «не-ссылочные» квадратные скобки уходят
  в `&#91;` / `&#93;`; обёртка `{{...}}` от разбора НЕ защищает.
- Обратный слэш НЕ экранирует — ломает разбор целиком, страница уезжает в макрос
  `unmigrated-wiki-markup`.
- `{...}` — вызов макроса; неизвестный макрос валит запрос с **HTTP 500** → фигурные
  скобки тоже экранируются (`&#123;` / `&#125;`).
- Чекбоксы `- [ ]` Confluence не понимает — маркер снимается.

**Callout-ы Obsidian → нативные панели.** Блок, первая строка которого имеет вид
`> [!тип] Заголовок`, становится макросом-панелью, заголовок уходит в `title=`:
`note`/`info` → `{info}` (синяя), `important` → `{note}` (жёлтая), `warning`/`caution`
→ `{warning}` (красная). Тип вне этой таблицы соответствия не выдумывается — блок
остаётся `{quote}` вместе с литеральным маркером. Заголовок с `{}`, `[]` или `|`
сломал бы разбор параметров макроса, поэтому уходит жирной первой строкой в тело.

## Registry

```json
{ "confluence_url": "...", "projects": { "<префикс>": {
    "space": "<SPACE>", "vaultRoot": "Company/Projects/<проект>",
    "map": [{ "obsidian": "<rel-путь>", "pageId": "…", "title": "…", "role": "section-index?" }]
} } }
```

Registry — личное состояние (реальные pageId инстанса): в публичный плагин не выгружается,
живёт только локально рядом со скриптом.
