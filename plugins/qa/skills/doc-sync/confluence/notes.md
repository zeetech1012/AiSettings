# Doc-sync → Confluence DC

> Адресатная часть скилла. Общие правила — в `SKILL.md` уровнем выше.
> Реестр `registry.json`, скрипты `upload.py` и `md2wiki.py` — рядом с этим файлом.
> `upload.py` ищет реестр в своём каталоге, поэтому они лежат вместе.
> Запуск: `cd ~/.claude/skills/doc-sync/confluence && python3 upload.py <SPACE> <prefix> "<vault-path>" --dry`


> Запись идёт **напрямую в REST API** (`/rest/api/content`) скриптом `upload.py`, а не через
> MCP `mcp-atlassian` (`confluence_*`): его markdown-конвертация лоссовая (та же проблема, что
> в Jira — см. skill `service-issue`), он не грузит дерево каталогов пакетно и не умеет
> mermaid → SVG-вложения. Читать/искать в сессии MCP-инструментами можно.

## Запуск

```bash
# сначала dry-run: печатает создать/обновить/переименовать без записи
python3 upload.py <SPACE> <проект-префикс> "Company/Projects/<проект>" --dry
# боевой прогон (родитель по умолчанию — homepage пространства)
python3 upload.py <SPACE> <проект-префикс> "Company/Projects/<проект>" [--parent <pageId>]
```

Зависимости: python3 (stdlib), `curl` (multipart-вложения), `npx` + Chromium
(`@mermaid-js/mermaid-cli` — рендер диаграмм; ставится сам при первом вызове).

**После переименований нужен второй прогон.** Карта ссылок (`LINKMAP`) читается из registry
при импорте модуля, а registry перезаписывается в конце прогона: на первом проходе ссылки
разрешаются в прежние заголовки.

## Как строится дерево

- Дерево vault → дерево страниц: подкаталог = страница-раздел, его файлы — дети.
- `README.md` каталога становится страницей-разделом этого уровня (корневой README —
  родителем всего дерева); каталог без README получает страницу-заглушку.
- **Заголовок страницы** = H1 файла с префиксом проекта: title в Confluence уникален
  в пределах ПРОСТРАНСТВА, а в vault имена типа `architecture_context.md` повторяются
  в каждом проекте. Коллизия внутри проекта → к заголовку добавляется имя файла.
- На страницах не указывается локальное расположение источника: ни путей vault, ни плашек «выгружено автоматически, правки в источник» (решение владельца 2026-09-24). Страница-раздел без README получает макрос `{children}`.
- Страница с шестью и более разделами второго уровня получает `{toc:maxLevel=2|minLevel=2}`
  перед первым разделом (`add_toc`). Макрос ставится при синхронизации, в исходнике vault
  оглавления нет: там его рисует сама Obsidian.
- Wikilinks разрешаются по registry в заголовки страниц (`resolve_links`), включая
  межпроектные; неизвестные цели остаются как есть.

## Ловушка — цепочка `ancestors` не пересчитывается у потомков

Страница переехала под нового родителя → у её **потомков** в REST-поле `ancestors` остаётся
прежний путь. Хлебные крошки в UI, дерево в боковой панели и запросы CQL `ancestor = <id>`
при этом верные (проверено на живом инстансе 2026-08-03) — расходится только это поле, то
есть страдают интеграции, которые его читают.

Лечится **реальной сменой родителя**: перенести страницу под другого родителя и вернуть
назад, PUT с телом из `body.storage`, чтобы содержимое осталось байт-в-байт. PUT с тем же
родителем поле не обновляет; endpoint `move` в Confluence DC 9.2.22 отсутствует (HTTP 404
на `/rest/api/content/{id}/move/{position}/{target}` и на `/rest/experimental/...`).

**Порядок — строго сверху вниз.** Цепочка вычисляется из цепочки родителя, поэтому лист,
починенный раньше своего родителя, скопирует битый путь. Чинить волнами: в каждой волне
только те страницы, чей родитель уже здоров.

Обычный прогон `upload.py` цепочки не портит и не лечит: он передаёт `ancestors` с прямым
родителем, а этого для пересчёта недостаточно.

## Mermaid

Confluence DC сам mermaid не рисует. `upload.py` рендерит блоки **поштучно** через `mmdc`
(одна битая диаграмма не валит остальные), кладёт `diagram-N.svg` вложениями страницы,
а `md2wiki.py` ставит в текст `!diagram-N.svg|width=900!` + исходник под `{expand}`.
Невалидные блоки перечисляются в конце прогона — чинить в источнике.

## md2wiki.py — правила, проверенные на живом инстансе

Конвертер собственный, порядок преобразований важен (код-блоки → блочные правила →
инлайн → экранирование). Ключевые ограничения Confluence wiki-разметки:

- `[текст]` — всегда ССЫЛКА, а не литерал → все «не-ссылочные» квадратные скобки уходят
  в `&#91;` / `&#93;`; обёртка `{{...}}` от разбора НЕ защищает.
- Обратный слэш НЕ экранирует — ломает разбор целиком, страница уезжает в макрос
  `unmigrated-wiki-markup`.
- `{...}` — вызов макроса; неизвестный макрос валит запрос с **HTTP 500** → фигурные
  скобки тоже экранируются (`&#123;` / `&#125;`).
- Чекбоксы `- [ ]` Confluence не понимает — маркер снимается.

**Callout-ы Obsidian → нативные панели.** Блок, первая строка которого имеет вид
`> [!тип] Заголовок`, становится макросом-панелью, заголовок уходит в `title=`:
`note`/`info` → `{info}` (синяя), `important` → `{note}` (жёлтая), `warning`/`caution`
→ `{warning}` (красная). Тип вне этой таблицы соответствия не выдумывается — блок
остаётся `{quote}` вместе с литеральным маркером. Заголовок с `{}`, `[]` или `|`
сломал бы разбор параметров макроса, поэтому уходит жирной первой строкой в тело.

## Registry

```json
{ "confluence_url": "...", "projects": { "<префикс>": {
    "space": "<SPACE>", "vaultRoot": "Company/Projects/<проект>",
    "map": [{ "obsidian": "<rel-путь>", "pageId": "…", "title": "…", "role": "section-index?" }]
} } }
```

Registry — личное состояние (реальные pageId инстанса): в публичный плагин не выгружается,
живёт только локально рядом со скриптом.

## Ловушка — префикс задаёт дерево: `Company/Projects` целиком выгружать нельзя

Прогон `upload.py API company-platform "Company/Projects"` (2026-08-12) выложил **весь**
export-слой одним «проектом» и создал второе дерево из 130 страниц поверх выгрузок по проектам:
заголовки различались префиксом (`company-platform — Архитектурный обзор` против
`auth_http — Архитектурный обзор`), поэтому идемпотентность по `(space, title)` дубль не заметила —
для неё это разные страницы.

Правило: **один префикс = один проект**, `vaultRoot` — каталог проекта, а не `Company/Projects`.
Разбор 2026-08-13: 130 страниц удалены (в корзину `API`), 120 оставшихся перевыложены из vault,
запись `company-platform` в реестре урезана до одной страницы без проектного аналога.

**Родитель дерева — `README.md` каталога, а не флаг запуска.** Проекты без README раскладывались
плоско на homepage: 44 страницы верхнего уровня в `API`. Лечится либо `--parent <id>` при каждом
прогоне (для проектов, чей индекс создан вручную в Confluence: `auth`, `auth_http`, `telecom`,
`company LK`, `uspd-ui`), либо переименованием обзорной заметки в `README.md` — тогда порядок
воспроизводится сам (так сделано для `platform-map`). После разбора верхний уровень — 14 проектных
корней вместо 44 страниц.

## `kd_upload.py` — конструкторская документация company Home

Отдельный адресат того же инстанса: источник не vault, а каталоги КД на диске
(`~/company product 2/company Home`), тело страницы собирается в **storage**-формате,
реестр свой — `kd_registry.json`.

```bash
python3 kd_upload.py <la25|hub|ezs> [--dry]
KD_CONF_IP=176.122.247.57 python3 kd_upload.py la25   # если split-DNS отдаёт мёртвый IP
```

- Дерево: изделие → страница на раздел (`<префикс> — <имя папки>`); подпапки внутри
  раздела — заголовки `h3`, файлы — вложения, PDF дополнительно рендерятся `viewpdf`.
- **Пространство не задаётся константой, а читается у страницы-родителя.** Confluence
  кладёт новую страницу в пространство предка и `space.key` из тела игнорирует: пилот
  просил `WAV`, страницы оказались в `WH`, а поиск по `(WAV, title)` их потом не находил —
  повторный прогон получил бы «title already exists» вместо обновления.
- Идемпотентность вложений — по паре **имя + размер** (`expand=extensions` отдаёт
  `fileSize`): размер иной → перезаливка версией через `/child/attachment/{id}/data`,
  совпал → пропуск. Это и есть механизм замены пересжатого видео.
- Видео берутся из каталога пересжатых (`.whome-video-compressed`), имя = путь от корня КД
  с `/` → `~`, у перекодированных `MOV` добавлен `.mp4`; имя вложения — человеческое.
  Оригиналы до 336 МБ лимит nginx (≈75 МБ) не проходят.
- Латинская буква между двумя кириллическими в имени папки чинится в заголовке страницы
  («Инcтрукция» → «Инструкция»); источник не правится, латинские аббревиатуры целы.
- Мусор (`.DS_Store`, `Thumbs.db`, `.msg`, `.db`), дубли имён в разделе и неудачные
  загрузки печатаются списками и пишутся в реестр — молча не теряется ничего.

## Ловушка — межпространственные ссылки без space-key (починено 2026-08-12)

Wiki-форма `[alias|Заголовок]` конвертируется Confluence в `ri:page` **без** `ri:space-key`:
цель ищется в пространстве текущей страницы. Ссылка из `WH` на статью в `API` при этом бьётся,
хотя выглядит валидной. `upload.py` теперь хранит в LINKMAP пару «заголовок + пространство» и
префиксует `SPACE:` каждую цель из чужого пространства (плюс прежний случай заголовка с
двоеточием). Все проекты, выгруженные до 2026-08-12, несли битые межпространственные ссылки —
исправлены массовой перевыгрузкой.

## Ловушка — переименование файла-источника в vault (2026-09-04)

Реестр сопоставляет страницу по относительному пути `obsidian`. Файл переименован через
`obsidian move` (ссылки в vault Obsidian чинит сам), но запись в реестре остаётся со старым
путём → следующий прогон не найдёт файл для существующей страницы и **создаст дубль** под
новым заголовком. Порядок: сначала поправить поле `obsidian` в записи (с бэкапом реестра),
затем `--dry` — он обязан показать `переименовать`/`обновить` для этой страницы и **ни одного
`создать`**, и только потом боевой прогон. Смена H1 без смены имени файла реестр не задевает:
она идёт как обычное `переименовать` плюс второй прогон для карты ссылок.

## Родитель корня дерева — `rootParentPageId` в registry (2026-09-04)

Полный прогон проекта без `--parent` и без `README.md` в каталоге раскладывал все страницы на
homepage пространства — так проект «Jira» (WAV) 1 и 2 сентября 2026 потерял структуру «статья
123456 под «Инструменты» + 8 подстатей»: точечные выгрузки 26–28.08 делались с явным родителем,
а полный прогон о нём не знал. Починка на уровне инструмента:

- `registry.projects[<prefix>].rootParentPageId` — id страницы, под которую кладётся корневой
  `README.md` проекта (или все файлы, если README нет). Не задано → homepage, как раньше.
  `--parent` в командной строке по-прежнему главнее.
- Точка входа дерева должна называться `README.md`: только её upload.py делает
  статьёй-родителем. Для «Jira» `jira-user-guide.md` переименован в `README.md`
  (`obsidian move`, запись реестра поправлена до прогона), `rootParentPageId = 123456`.

Проверка после любого прогона: цепочка `ancestors` у случайной подстатьи должна содержать
статью-родителя, а не только homepage.

## Заголовки: шапка = имя раздела, дети «Тема (код)» (2026-09-04)

Решение владельца 2026-09-04: полный префикс «Назначение (код)» несёт только страница-шапка
раздела (корневой `README.md` → заголовок равен ключу реестра, H1 игнорируется); вложенные
страницы называются темой с кодом в скобках — «Архитектура (auth_http)», «Путь данных (appsandbox)».
Код берётся `code_of()` из скобок в конце ближайшей шапки: ключа реестра или H1 README подраздела
(«Шлюз Яндекс Умного дома (yandex-gw)» даёт детям `yandex-gw`). Шапка без скобок («Платформа company:
контуры», «Тестирование backend») — дети без хвоста. Если в H1 уже есть свои скобки в конце
(«Схема — API Connectivity Map (v2)», «… (example.com)»), хвост не добавляется.

Почему код обязателен: заголовок уникален в пространстве, а «Архитектура» есть у каждого сервиса.
Канон тем после унификации 2026-09-04: Зачем сервис · Архитектура · Путь данных · Контракт API ·
Сборка и запуск · Спецификации API (подраздел) · Спецификация OpenAPI / AsyncAPI. Уточнения
темы через двоеточие сняты («Путь данных: синхронизация с Omnidesk» → «Путь данных»), уникальные
темы оставлены как есть.

Сопутствующие правки `upload.py` (бэкап `upload.py.bak-childtitles-2026-09-04`):

- `upsert` ищет страницу **сначала по id из реестра**, потом по заголовку; если заголовок занят
  другой страницей — прогон останавливается. Раньше поиск по заголовку шёл первым: с короткими
  именами второй сервис перезаписал бы страницу первого.
- `README.md`, появившийся в каталоге-заглушке (`section-stub`, ключ `rel/`), переиспользует
  pageId заглушки — так «api-specs» стал «Спецификации API (serversoft)» без новой страницы.

Второй прогон ради ссылок больше не нужен: `relink.py <бэкап реестра> [--apply]` строит карту
old→new по pageId (бэкап против текущего реестра), обходит пространства и правит только
`ri:content-title` у битых ссылок, один PUT на страницу. 2026-09-04: 53 страницы, 164 ссылки,
в том числе входящие из LK и WH. Ловушка при сборке тега: у самозакрывающегося `<ri:page … />`
группа после `ri:content-title` захватывает « /», без среза получается `//>` и Confluence отвечает
400 «Error parsing xhtml».

Ловушка `obsidian move`: Obsidian переписывает входящие ссылки в **короткую форму**
`[[Имя файла|подпись]]`, а `LINKMAP` знает только полные пути — после переименования
«QA Context — API-контракт фронтенда uspd-ui» восемь ссылок в семи файлах uspd-ui ушли в Confluence
сырым текстом. После любого `obsidian move` проверять `grep -rhoE "\[\[[^]|#]+" | grep -v "\[\[Company/"`.

Уточнение правила шапки (2026-09-04, вечер): если H1 корневого `README.md` начинается с ключа реестра
(«Jira — как устроены проекты и как с ними работать» при ключе «Jira»), заголовком остаётся весь H1;
иначе заголовок равен ключу. Без этого прогон проекта «Jira» переименовал бы корень WAV в «Jira».

## `--parent` и дерево из одного `README.md` (2026-09-25)

С ключом `--parent` `upload.py` пропускает блок корневого `README.md` целиком (он выполняется только при `parent is None`),
а `README.md` исключён из списка обычных файлов. Дерево из одного `README.md` с `--parent` даёт пустой прогон с кодом 0
и без единой строки вывода. Для нового дерева под разделом: сначала запись `registry.projects[<prefix>]` с `space`,
`vaultRoot`, `rootParentPageId` и пустым `map` (бэкап реестра рядом), затем прогон без `--parent`: сухой обязан показать
`создать [родитель] <заголовок>`. Так выложены «Как вести тестирование ПО в Jira Xray» (123456) и «ОТК в Jira Xray:
обоснование» (123456) под «Процессы» 123456. Метки страниц `upload.py` не ставит: `POST /rest/api/content/<id>/label`.

- **Выдержки и список дочерних страниц ставятся при выгрузке (2026-09-30).** md2wiki экранирует `{`…`}`, поэтому макросы в markdown не пишутся. `add_toc` вызывает `add_lead_excerpt` (первая фраза выноски `> …` в начале статьи → `{excerpt}`) и `add_children` (пустой раздел «Страницы раздела» → `{children:excerptType=simple}`). Выдержка = первая фраза выноски: она должна говорить, о чём статья. Без `{excerpt}` на дочерних страницах макрос показывает только заголовки.
- **Жирный во вложенном пункте списка** (`   - **Поле**: …`) md2wiki отдаёт как `* *Поле**`, в Confluence видна звёздочка. Во вложенных пунктах жирный не использовать.
- **Точечная выгрузка и родитель.** `upsert` ставит `ancestors` и при обновлении: передавать текущего родителя страницы из Confluence, иначе страница переедет.

## Перенос в другое пространство и закрепления `pins` (2026-10-08)

`PUT /rest/api/content/{id}` со сменой `space` в DC 9.2 отвечает 400 «You can't change an existing page's space».
Переносит `POST /pages/movepage.action?pageId=<id>&spaceKey=<KEY>&targetTitle=<заголовок родителя>&position=append`
с заголовком `X-Atlassian-Token: no-check` и Bearer-токеном. Задача фоновая: ответ 200 приходит раньше переноса,
результат подтверждать опросом `space` и `ancestors`. Поддерево, версии, история и вложения переезжают вместе с корнем.

Страница, перенесённая из дерева своего проекта, закрепляется в `registry.json` → `pins`
(`kd_registry.json` → `pins` для `kd_upload.py`): `{"<pageId>": {"space", "parentPageId", "note"}}`.
`upsert` берёт пространство и родителя из закрепления, ссылки на страницу получают префикс пространства закрепления.
Без закрепления прогон проекта отправит PUT со старым пространством и упадёт с той же ошибкой 400.
Так в WQA живут сервисные QA-описания, срезы 08.09, yandex-gw и методики ОТК.
