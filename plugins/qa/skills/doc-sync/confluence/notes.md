# Doc-sync → Confluence DC

> Адресатная часть скилла. Общие правила — в `SKILL.md` уровнем выше.
> Реестр `registry.json`, скрипты `upload.py` и `md2wiki.py` — рядом с этим файлом.
> `upload.py` ищет реестр в своём каталоге, поэтому они лежат вместе.
> Запуск: `cd ~/.claude/skills/doc-sync/confluence && python3 upload.py <SPACE> <prefix> "<vault-path>" --dry`


> Запись идёт **напрямую в REST API** (`/rest/api/content`) скриптом `upload.py`, а не через
> MCP `mcp-atlassian` (`confluence_*`): его markdown-конвертация лоссовая (та же проблема, что
> в Jira — см. skill `jira-service-issue`), он не грузит дерево каталогов пакетно и не умеет
> mermaid → SVG-вложения. Читать/искать в сессии MCP-инструментами можно.

## Запуск

```bash
# сначала dry-run: печатает создать/обновить/переименовать без записи
python3 upload.py <SPACE> <проект-префикс> "Company/Projects/<проект>" --dry
# боевой прогон (родитель по умолчанию — homepage пространства)
python3 upload.py <SPACE> <проект-префикс> "Company/Projects/<проект>" [--parent <pageId>]
```

Зависимости: python3 (stdlib), `curl` (multipart-вложения), `npx` + Chromium
(`@mermaid-js/mermaid-cli` — рендер диаграмм; ставится сам при первом вызове).

Два скрипта-спутника рядом с `upload.py`, оба работают по тому же реестру:

```bash
# README проекта на уже существующую страницу-индекс раздела (upload.py с --parent его не публикует)
python3 publish_index.py <префикс-реестра> "<vault-путь-README>" <pageId-индекса>
# перелинковка после массового переименования: старый заголовок ссылки -> новый
python3 relink.py <registry.json.bak-…> [--apply]
```

**После переименований нужен второй прогон.** Карта ссылок (`LINKMAP`) читается из registry
при импорте модуля, а registry перезаписывается в конце прогона: на первом проходе ссылки
разрешаются в прежние заголовки.

## Как строится дерево

- Дерево vault → дерево страниц: подкаталог = страница-раздел, его файлы — дети.
- `README.md` каталога становится страницей-разделом этого уровня (корневой README —
  родителем всего дерева); каталог без README получает страницу-заглушку.
- **Заголовок страницы** = H1 файла с префиксом проекта: title в Confluence уникален
  в пределах ПРОСТРАНСТВА, а в vault имена типа `architecture_context.md` повторяются
  в каждом проекте. Коллизия внутри проекта → к заголовку добавляется имя файла.
- Внизу каждой страницы — `{info}`-футер «источник — такой-то путь в vault, правки в источник».
- Страница с шестью и более разделами второго уровня получает `{toc:maxLevel=2|minLevel=2}`
  перед первым разделом (`add_toc`). Макрос ставится при синхронизации, в исходнике vault
  оглавления нет: там его рисует сама Obsidian.
- Wikilinks разрешаются по registry в заголовки страниц (`resolve_links`), включая
  межпроектные; неизвестные цели остаются как есть.

## Ловушка — цепочка `ancestors` не пересчитывается у потомков

Страница переехала под нового родителя → у её **потомков** в REST-поле `ancestors` остаётся
прежний путь. Хлебные крошки в UI, дерево в боковой панели и запросы CQL `ancestor = <id>`
при этом верные (проверено на живом инстансе 2026-08-03) — расходится только это поле, то
есть страдают интеграции, которые его читают.

Лечится **реальной сменой родителя**: перенести страницу под другого родителя и вернуть
назад, PUT с телом из `body.storage`, чтобы содержимое осталось байт-в-байт. PUT с тем же
родителем поле не обновляет; endpoint `move` в Confluence DC 9.2.22 отсутствует (HTTP 404
на `/rest/api/content/{id}/move/{position}/{target}` и на `/rest/experimental/...`).

**Порядок — строго сверху вниз.** Цепочка вычисляется из цепочки родителя, поэтому лист,
починенный раньше своего родителя, скопирует битый путь. Чинить волнами: в каждой волне
только те страницы, чей родитель уже здоров.

Обычный прогон `upload.py` цепочки не портит и не лечит: он передаёт `ancestors` с прямым
родителем, а этого для пересчёта недостаточно.

## Mermaid

Confluence DC сам mermaid не рисует. `upload.py` рендерит блоки **поштучно** через `mmdc`
(одна битая диаграмма не валит остальные), кладёт `diagram-N.svg` вложениями страницы,
а `md2wiki.py` ставит в текст `!diagram-N.svg|width=900!` + исходник под `{expand}`.
Невалидные блоки перечисляются в конце прогона — чинить в источнике.

## md2wiki.py — правила, проверенные на живом инстансе

Конвертер собственный, порядок преобразований важен (код-блоки → блочные правила →
инлайн → экранирование). Ключевые ограничения Confluence wiki-разметки:

- `[текст]` — всегда ССЫЛКА, а не литерал → все «не-ссылочные» квадратные скобки уходят
  в `&#91;` / `&#93;`; обёртка `{{...}}` от разбора НЕ защищает.
- Обратный слэш НЕ экранирует — ломает разбор целиком, страница уезжает в макрос
  `unmigrated-wiki-markup`.
- `{...}` — вызов макроса; неизвестный макрос валит запрос с **HTTP 500** → фигурные
  скобки тоже экранируются (`&#123;` / `&#125;`).
- Чекбоксы `- [ ]` Confluence не понимает — маркер снимается.

**Callout-ы Obsidian → нативные панели.** Блок, первая строка которого имеет вид
`> [!тип] Заголовок`, становится макросом-панелью, заголовок уходит в `title=`:
`note`/`info` → `{info}` (синяя), `important` → `{note}` (жёлтая), `warning`/`caution`
→ `{warning}` (красная). Тип вне этой таблицы соответствия не выдумывается — блок
остаётся `{quote}` вместе с литеральным маркером. Заголовок с `{}`, `[]` или `|`
сломал бы разбор параметров макроса, поэтому уходит жирной первой строкой в тело.

## Registry

```json
{ "confluence_url": "...", "projects": { "<префикс>": {
    "space": "<SPACE>", "vaultRoot": "Company/Projects/<проект>",
    "rootParentPageId": "…",
    "map": [{ "obsidian": "<rel-путь>", "pageId": "…", "title": "…", "role": "section-index?" }]
} } }
```

Registry — личное состояние (реальные pageId инстанса): в публичный плагин не выгружается,
живёт только локально рядом со скриптом.

## Ловушка — префикс задаёт дерево, целиком export-слой выгружать нельзя

Прогон с `vaultRoot`, равным корню export-слоя (`Company/Projects`), выложил весь слой одним
«проектом» и создал второе дерево из 130 страниц поверх выгрузок по проектам. Идемпотентность
по паре «пространство и заголовок» дубль не заметила: заголовки различались префиксом
(`платформа — Архитектурный обзор` против `auth_http — Архитектурный обзор`), то есть для
проверки это разные страницы. Разбор занял день: 130 страниц в корзину, 120 оставшихся
перевыложены из vault.

Правило: **один префикс реестра = один проект**, `vaultRoot` указывает на каталог проекта.

**Родитель дерева — `README.md` каталога, а не флаг запуска.** Проект без README раскладывается
плоско на homepage пространства: так однажды получилось 44 страницы верхнего уровня. Лечится либо
`--parent <id>` при каждом прогоне (для проектов, чей индекс создан в Confluence руками), либо
переименованием обзорной заметки в `README.md` — тогда порядок воспроизводится сам.

## Ловушка — межпространственные ссылки без space-key

Wiki-форма `[alias|Заголовок]` конвертируется Confluence в `ri:page` **без** `ri:space-key`: цель
ищется в пространстве текущей страницы. Ссылка на статью в другом пространстве при этом бьётся,
хотя выглядит валидной. `upload.py` хранит в карте ссылок пару «заголовок и пространство» и
префиксует `ПРОСТРАНСТВО:` каждую цель из чужого пространства (тот же префикс закрывает прежний
случай заголовка с двоеточием). Всё, что выгружено до этой правки, несло битые межпространственные
ссылки и потребовало массовой перевыгрузки.

## Ловушка — переименование файла-источника в vault

Реестр сопоставляет страницу по относительному пути `obsidian`. Файл переименован через
`obsidian move` (ссылки внутри vault Obsidian чинит сам), а запись в реестре осталась со старым
путём — следующий прогон не найдёт файл для существующей страницы и **создаст дубль** под новым
заголовком.

Порядок: сначала поправить поле `obsidian` в записи, сделав бэкап реестра; затем `--dry`, который
обязан показать «переименовать» или «обновить» для этой страницы и **ни одного «создать»**; только
потом боевой прогон. Смена H1 без смены имени файла реестр не задевает.

Вторая ловушка того же `obsidian move`: Obsidian переписывает входящие ссылки в **короткую форму**
`[[Имя файла|подпись]]`, а карта ссылок знает только полные пути — после переименования такие
ссылки уезжают в Confluence сырым текстом. После любого перемещения проверять короткие wikilinks:

```bash
grep -rhoE "\[\[[^]|#]+" <vault-путь-проекта> | grep -v "\[\[Company/"
```

## Родитель корня дерева — `rootParentPageId` в реестре

Полный прогон проекта без `--parent` и без `README.md` в каталоге раскладывал страницы на homepage
пространства. Так проект, чьи точечные выгрузки делались с явным родителем, при первом полном
прогоне потерял структуру «страница-раздел плюс восемь подстатей». Починка на уровне инструмента:

- `registry.projects[<префикс>].rootParentPageId` — id страницы, под которую кладётся корневой
  `README.md` проекта (или все файлы, если README нет). Не задано — homepage, как раньше.
  `--parent` в командной строке по-прежнему главнее.
- Точка входа дерева должна называться `README.md`: только её `upload.py` делает страницей-родителем.

Проверка после любого прогона: цепочка `ancestors` у случайной подстатьи содержит страницу-родителя,
а не только homepage.

## Заголовки: шапка = имя раздела, дети «Тема (код)»

Полный префикс «Назначение (код)» несёт только страница-шапка раздела: корневой `README.md`
получает заголовок, равный ключу реестра, а его H1 игнорируется. Исключение — H1, начинающийся с
самого ключа: он остаётся заголовком целиком. Вложенные страницы называются темой с кодом в
скобках: «Архитектура (auth_http)», «Путь данных (uspd-ui)».

Код берётся из скобок в конце ближайшей шапки — ключа реестра или H1 README подраздела, так что
подраздел со своим кодом передаёт его своим детям. Шапка без скобок даёт детям заголовки без
хвоста. Если в H1 уже есть свои скобки в конце, хвост не добавляется.

Почему код обязателен: заголовок уникален в пределах пространства, а «Архитектура» есть у каждого
сервиса.

Сопутствующие правила в `upload.py`:

- `upsert` ищет страницу **сначала по id из реестра**, потом по заголовку. Если заголовок занят
  другой страницей, прогон останавливается. При обратном порядке короткое имя второго сервиса
  перезаписало бы страницу первого.
- `README.md`, появившийся в каталоге-заглушке, переиспользует её `pageId`: раздел получает
  нормальное имя без новой страницы.

**Второй прогон ради ссылок больше не нужен.** `relink.py` строит карту «старый заголовок → новый»
по `pageId` (бэкап реестра против текущего), обходит пространства из реестра и правит только
`ri:content-title` у битых ссылок, один PUT на страницу. Порядок величин на массовом переименовании:
полсотни страниц и полторы сотни ссылок без единой перевыгрузки. Ловушка при сборке тега: у
самозакрывающегося `<ri:page … />` группа после `ri:content-title` захватывает « /», и без среза
получается `//>`, на который Confluence отвечает 400 «Error parsing xhtml».
